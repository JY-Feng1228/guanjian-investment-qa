# 评测设计与解释边界

当前规则评测器为`rules-1.2.1`，实现位于`lib/evaluator.ts`；质量验收的原始基线`rules-1.1.1`单独封存，`rules-1.2.0`作为历史回归保留在Git中。首轮8条Luna复核、第二轮16次双模型与修订稿复核分别留档，网页在线付费调用关闭。本文区分规则流程、模型调用、二元告警一致性和未完成的独立质量评测。

## 样本与证据

`lib/seed.ts` 包含 **8 个独立问题 × 2 种匿名画像 × 2 个版本＝32 份构造回答**。其中 5 个事实查询问题、3 个解释问题，展开后分别为 20、12 份回答。画像和版本扩展没有增加独立问题数。

| 问题 | 意图 | 主要检查场景 |
| --- | --- | --- |
| Q01 | 事实查询 | 收入与利润金额错误 |
| Q02 | 事实查询 | 营业收入、营业总收入与接口单位混淆 |
| Q03 | 事实查询 | 把 2024 年数值用作 2023 年基数 |
| Q04 | 证据解释 | 将历史年报当作当日最新消息 |
| Q05 | 证据解释 | 无证据因果推断；新版本仍保留收益确定性问题 |
| Q06 | 事实查询 | 现金流事实未登记，需补证；不代表年报未披露 |
| Q07 | 事实查询 | 同一事实随画像变化 |
| Q08 | 证据解释 | 保证收益及激进行动表述 |

样例由 AI 助手辅助构造，包含人为设定的错误、修正和遗留问题。它们用于演示发现、复核、修订、回归的完整路径，**不是实际模型输出、随机抽样测试集或独立盲评集**。不能用这批数据宣称模型准确率、召回率或质量提升百分比；当前也没有已冻结并完成独立标注的留出测试集。

第二批另有12个新构造问题H01–H12，在基线运行前未参与已有检测器调试；其标签为AI预标注。用户转发的外部AI截图明确未直接读取PDF，不视为用户本人核对或专家标签。两个回答修订案例与3条离线挑战单独记录，不加入初始32条样本的数量或双模型六题分母。

S1 为已逐项核对的官方年报事实快照。S2、S3 为真实 iFinD 查询的脱敏摘录，保留已发现的口径和摘要冲突。数字核验仅使用 `kind: "official"` 且 `status: "verified"` 的登记事实；接口摘要不自动成为真值。原文核对范围见 [核验记录](../public/evidence/moutai-2024-verification.json)，完成方式见 [AI 使用说明](AI-USAGE.md)。

## 判定与覆盖率

| 状态 | 当前含义 |
| --- | --- |
| `supported` 有证据支持 | 已识别的数值断言与登记事实在单位、期间及显示精度下相符；不表示整篇回答正确 |
| `contradicted` 发现冲突 | 数值或期间冲突、跨画像数值变化，或命中确定性收益等产品规则；后者不是法律合规认证 |
| `unverifiable` 无法核验 | 缺少对应证据、数字未解析或历史证据不能支持当前行情；不等于回答错误 |
| `review` 待复核 | 因果、相关性、来源冲突或其他规则疑点，需要复核 |

规则回答整体状态按“发现冲突 → 待复核 → 无法核验 → 有证据支持”的优先级汇总。查看整体标签时仍需阅读各条发现与方法字段。模型疑点在独立区域展示，不覆盖该规则标签。

**数字核验覆盖率仅为 `checkedClaims / totalClaims`。**

- `checkedClaims`：产生“数字”维度的支持或冲突结果的断言数量；冲突也算已核验，覆盖率不是正确率。
- `totalClaims`：当前代码取“带货币单位或百分号的数值片段数”与“成功提取的指标断言数”两者较大值，并非所有事实陈述数量。
- 工作台按每条回答的最新规则评测汇总这两个数量；模型记录不混入规则统计。分母为 0 时无覆盖率，不解释为全部通过。

## 第一批真实语义复核：8条

本批次在调用前固定 `Q01-novice-v2`、`Q02-experienced-v1`、`Q03-novice-v1`、`Q04-experienced-v1`、`Q05-novice-v2`、`Q06-experienced-v1`、`Q07-novice-v1`、`Q08-experienced-v2`，8 个独立问题各尝试一次。没有实际生成回答，也没有重试或替换失败样本；被复核回答的 `provenance: "constructed"` 保持不变。

官方 `gpt-6-luna` 使用 `quality-v1` 提示词，仅对给定问题、回答及证据提出语义疑点。6 条成功、2 条失败，成功记录共 10 条疑点；Q08 返回零疑点，仅表示本次模型未指出问题。Q01 网络错误保留未知用量，Q07 格式或引用校验失败保留已返回 usage，未保留原始响应，无法细分原因。记录、用量与失败见 [公开快照](../public/evidence/openai-review-20261025.json)及[测试记录](TESTING.md)。

**6 / 8 只表示调用完成率。** 成功不等于判断正确，失败不是回答质量差，零疑点不是通过。该批次不是随机抽样、留出测试或盲评；没有独立标注分母，因此不计算准确率、召回率、模型优劣或 Prompt 提升比例。

`lib/model-snapshot.ts` 用输入哈希绑定原样本内容、版本、匹配证据、请求模型与提示词版本，只有匹配时载入旧记录。界面分别查看规则与模型发现；财务事实结论仍依据已登记证据及规则。模型只能输出 `review` 或 `unverifiable`，不得直接把疑点转为官方事实判定。对后续导入或修订的回答不会自动套用该快照，也不会自动发起付费请求。

第二批16次全部成功，不含重试或替换；总保守费用估算$0.09843175，无未知费用。该批预算$0.50与第一批$0.30及其未知费用预留分开。详细记录见 [质量验收说明](QUALITY-VALIDATION.md)。

二元指标的正例定义为参考标签`needsReview=true`；模型有至少一条疑点视为触发告警，规则只计具体缺陷告警，排除通用解析/覆盖不足提示。TP/FP/FN/TN只回答“有没有告警”，不要求告警理由或维度与参考问题一致。因此还须逐项核对，例如H04/H08不能凭TP宣称正确定位，Luna在H12的两个重叠疑点也不是两个独立错误。

指标中的precision为TP/(TP+FP)，recall为TP/(TP+FN)，agreement为(TP+TN)/成功取得判定的样本数；分母为0时不输出比例。这些均限于当前预标注和二元告警任务，不作为业务整体准确率。主模型比较只使用双方共同成功的相同题目；各自成功子集结果与尝试、成功、失败、未尝试、进行中数量另列，失败或未调用不当作阴性。当前全部成功，所以共同分母均为6。

后续 [逐项证据核对](../public/evidence/quality-adjudication-20261025.json)保留原报告哈希，以`findingId`关联原输出，不改参考标签、原矩阵或原发现。核对方法是AI工具核对，不是用户人工确认。六题相同结果不能证明Sol优于Luna；当前保留Luna为成本基线，复杂任务优劣未验证。

两份改善案例由AI助手依据证据修改回答，前后由同版规则回归，模型仅检查after稿；没有真正生成Prompt的受控前后实验，不据此宣称Prompt优化效果。看过基线发现后再修改规则，同批12题也失去“未参与调试”的条件，新规则结果必须单列为开发回归。

开发回归见 [单独记录](../public/evidence/quality-regression-20261025.json)。本次1.2.1中，C01的小数误差和C03的报告期错置发现未变；C02先得到“营业收入与原文一致”，再得到“回答指标可能偏离问题”，替代1.2.0错误的主体理由。H08保留切题性告警，附带主体误报消失。二元矩阵仍为6/0/0/6，说明相同矩阵可能对应不同理由质量。评价时点固定沿用初测的`2026-10-25T00:00:00Z`，文件实际生成时间另记，避免以运行日变化造成时效比较差异。

1.2.0曾遗漏初始32条演示回答的专项回归：主体识别误报8条，Q01/Q02中4处营收错误未再得到数字冲突。1.2.1将主体判断限制在直接金额断言前，补充`tests/seed-regression.test.ts`后，32条主体误报为0，四处营收数字冲突恢复；旧规则和报告可从提交`ac56ad4f51e4cc258084f38d3279e97a1a774d53`查看。此次教训是既要验证新案例，也要回归原有演示数据，二元告警之外还要检查理由和数字核验是否被意外跳过。

## 配对与版本对比

界面可选择三个比较轴，每次只改变一个轴：

| 比较轴 | 固定条件 |
| --- | --- |
| Prompt | `questionId`、`profileId`、`modelVersion`、`dataVersion`、`evaluatorVersion` |
| 模型 | `questionId`、`profileId`、`promptVersion`、`dataVersion`、`evaluatorVersion` |
| 数据 | `questionId`、`profileId`、`promptVersion`、`modelVersion`、`evaluatorVersion` |

两侧必须有规则评测、版本不同且能唯一配对；缺少对应样本、多个候选或评测器版本不同均不计算配对变化。所选轴只有一个版本时显示空态。初始模型字段明确为“构造示例 · 无模型生成”，指回答的生成来源，不是语义复核所用的 `gpt-6-luna`；不能把字段相同理解为已执行真实受控模型实验。真实语义复核记录不混入三轴规则对比。

新增样本可提供三个顶层可选版本字段；前端省略空值，服务端应用默认标签。同题文本去空白并忽略英文大小写后复用 `questionId`，不做语义近义归并。相同问题、画像、三轴版本完整组合重复时拒绝导入。

**用户填写的 `dataVersion` 是回答生成时的数据上下文标签，不是核验数据上传入口。** 核验仍使用固定的官方证据集。模型标签也是导入者声明；比较能检查所给回答的差异，但不能证明标签真实或模型、数据改变造成因果效果。

界面按发现的维度、事实字段与标题匹配“未再出现、新增、遗留”项。未再检出可能来自表达变化或解析盲区，不能自动认定已经修复。保存修订回答时保留旧版本与旧评测，新一轮复核结论不从旧评测自动继承。

部署规则升级不会自动重写已有浏览器空间的评测。点击“核验当前列表”会追加当前版本的结果，旧历史与复核绑定保留；新空间直接使用当前规则，不通过清库刷新结果。

跨画像检查则固定问题、Prompt、模型和数据版本，只改变画像，比较已解析的相同指标与期间数值；允许显示精度导致的四舍五入差异。它只验证已提取事实的一致性，不证明所有个性化表达都合适。

## 人工复核与用户反馈

`confirmed`、`false_positive`、`needs_data` 是访客对某次评测主动提交的复核声明，初始数据不预填人工确认。当前演示没有审核员身份认证或双人裁决；因此这些记录不构成认证标注集。复核保留原始机器判定和说明。

`useful`、`not_useful`、`dispute` 是使用体验或异议反馈，记录来源为 `visitor`。反馈可以提示调查方向，但不直接改写事实状态，不能作为模型训练真值或准确率分母。

## 已知边界与验证方法

数值解析器依赖已登记的指标名称、阿拉伯数字、相邻金额及单位，并结合局部句子和问题推断期间。当前已区分明确的年度、Q1–Q4、H1/H2 和前三季度累计期间；主体检查限于直接金额断言前的主体位置，出现不同主体疑点时暂停数字核验，带金额后缀的数值不会仅因形似手机号而被拦截。跨句主体、复杂省略、多期并列、同比计算、否定与引用语境仍可能无法完整识别或产生误报。单位换算、主体识别和精度容差是有限规则，不补足全面语义理解。

`tests/evaluator.test.ts` 覆盖数值、单位、期间、证据缺失、时效、因果疑点、否定表达、跨画像一致性、未解析数字和来源冲突，以及季度与全年、不同公司主体等边界。隐私测试验证金额与手机号的区分。`tests/model.test.ts` 的 mock 验证请求限制、提示词边界、结构化解析、引用校验、拒绝与请求元数据、超时、不重试及未知用量处理；`tests/model-budget.test.ts` 验证未知费用预留与预算门槛。这些测试不衡量真实模型能力。

当前43项单元测试及类型检查通过；HTTP、构建、浏览器与视频最终状态见 [测试记录](TESTING.md)，不以旧版的结果替代。实现检查不能转换为金融事实识别准确率。本次修复没有新增模型调用；两批费用授权均只覆盖各自固定计划，新的调用需另行明确范围与预算。独立事实标注及未参与调整的新样本仍未完成。
