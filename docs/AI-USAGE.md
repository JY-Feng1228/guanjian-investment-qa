## 模型适配器的限制

`lib/model.ts` 固定请求官方 Responses API 的 `gpt-6-luna`，提示词版本为 `quality-v1`，使用 `reasoning.effort: "none"`、`store: false` 和 `strict: true` 的 JSON Schema，最多输出 1,200 token，20 秒超时且不自动重试。不向模型开放工具；问题、回答和证据作为不可信数据处理。返回需通过结构、证据 ID 和原文引用校验；模型疑点只能标为“待复核”或“无法核验”，不能直接成为官方事实结论。空 `findings` 仅表示未提出疑点，不代表回答正确。

模型快照通过输入 SHA-256 绑定原回答、版本、匹配证据、请求模型与提示词版本；输入变化时不复用旧结果。规则统计及版本对比继续只使用规则结果，模型记录作为独立补充。本批次没有实际生成回答，也没有独立真值标注，不能声称 answer-v2 的真实质量已高于 answer-v1。

工作台支持以 Prompt、模型、数据任一轴做单变量版本对照，固定问题、画像、其余两轴及评测器版本。导入时填写的模型与数据标签是提交者声明，不是平台已验证的模型调用记录或新证据集；改变 `dataVersion` 不会改变当前官方核验快照。只有一个版本时不显示成对效果结论。

## 受控调用与授权边界

`scripts/verify-openai.ts` 默认 `--plan`，仅检查计划与 ledger，不调用 API。`--probe` 请求固定首条；`--continue` 仅处理未尝试条目；有失败时必须先诊断，再显式使用 `--continue-after-diagnosis` 处理剩余不同问题。所有模式均保留既有尝试，失败后停止当前执行，不自动重试。

每次请求前先检查剩余预算，再将本次尝试及费用预留写入 ledger，保存后才发出网络请求。私有 ledger 位于被 Git 忽略的 `private/`，公开快照仅包含可审阅的输入哈希、结果、失败及用量元数据。密钥仅从已有 `OPENAI_API_KEY` 读取，不写入源码、浏览器或公开快照。

**本次固定 8 条已完成，$0.30 不是循环授权。** 不应删除 ledger、替换失败样本或重建同一批次以再次执行；新的模型调用需另行明确范围与预算。运行网页、单元测试、HTTP 验收和查看快照均不需要执行该付费脚本。
